# Локальная проверка PostgREST в Docker

Последнее обновление: 13.09.2026

## Когда нужна

Когда изменение схемы может поменять то, как PostgREST понимает запросы
приложения, а проверить это на бою нельзя:

- новая связь между таблицами (внешний ключ, таблица связи, вьюха), особенно
  к `wines`, `wineries`, `offers` — их embed'ы шлёт уже установленное
  приложение, исправить его в сторах нельзя;
- вопрос «сломает ли это старую сборку» (сейчас у пользователей 1.1.0);
- любое поведение PostgREST, которое зависит от кэша схемы.

Для проверки SQL-логики (триггеры, RPC, данные) это не нужно: там работает
транзакция с откатом на VPS или скрипт в `supabase/tests/`.

## Почему не на VPS

Кэш схемы у боевого PostgREST один на всех: пробная таблица, увиденная им,
видна и приложению. Запуск второго контейнера на боевом сервере с его
паролями автоматический режим Claude Code блокирует — и правильно. Поэтому
проверка идёт на компьютере разработчика, на пустой базе, без боевых
данных и паролей.

## Что нужно

- Docker Desktop (на рабочем компьютере установлен, 29.x).
- Запустить, если не запущен:

  ```powershell
  Start-Process "C:\Program Files\Docker\Docker\Docker Desktop.exe"
  ```

  Готовность — команда отвечает номером версии (до минуты после запуска):

  ```bash
  docker info --format '{{.ServerVersion}}'
  ```

  Ошибка `failed to connect to the docker API … dockerDesktopLinuxEngine`
  значит, что Docker Desktop ещё не поднялся или не запущен.
- Та же версия PostgREST, что на бою. Узнать (только чтение):

  ```bash
  ssh -i ~/.ssh/winepool_vps root@91.227.18.214 "docker ps --format '{{.Names}} {{.Image}}' | grep rest"
  ```

  На 13.09.2026 — `postgrest/postgrest:v14.8`. Для проверки связей базе
  хватает `postgres:15`; расширения и роли Supabase не нужны.

## Готовый скрипт

`tool/probe_postgrest_wine_production_embed.sh`, запуск из Git Bash:

```bash
bash tool/probe_postgrest_wine_production_embed.sh
```

Что он делает:

1. Создаёт сеть `pgrst_probe_net` и контейнер `pgrst_probe_db` с Postgres.
2. Для каждого варианта (`run_case`) пересоздаёт схему `public` из DDL
   варианта, выдаёт роли `anon` чтение и поднимает `pgrst_probe_api`
   (PostgREST) на `127.0.0.1:39999`.
3. Ждёт, пока PostgREST загрузит кэш схемы, и выполняет запросы варианта.
4. В конце удаляет оба контейнера и сеть.

Первый запуск скачивает образы, это несколько минут. Дальше прогон всех
вариантов — около минуты.

## Как добавить свой вариант

Скопировать скрипт под свою задачу (`tool/probe_postgrest_<тема>.sh`) и
описать варианты:

```bash
run_case "название варианта" \
  "create table public.wines(...); create table public.новая_таблица(...);" \
  "wines?select=id,wineries(*) wines?select=id,новая_таблица(...)"
```

- Второй аргумент — DDL. Таблица `wineries` создаётся заранее, остальные —
  здесь. Данные не нужны: связи PostgREST определяет по схеме.
- Третий аргумент — запросы через пробел, в форме PostgREST
  (`таблица?select=...`). Первым ставить запрос **в той форме, которую шлёт
  старая сборка**: его нельзя поменять.
- Вариант «как сейчас» держать первым, чтобы было с чем сравнивать.

## Как читать ответы

| Ответ | Значит |
|---|---|
| `[]` | Запрос понят. Пустой массив — просто нет данных |
| `PGRST201` | Неоднозначный embed: между таблицами несколько связей. Старая сборка с этим запросом сломается |
| `PGRST200` | Связи нет вовсе |
| `PGRST002` | PostgREST ещё грузит кэш схемы — скрипт ждёт этого сам; если осталось в выводе, увеличить ожидание |

## Уборка вручную

Если скрипт прервали:

```bash
docker rm -f pgrst_probe_api pgrst_probe_db
docker network rm pgrst_probe_net
```

Docker Desktop после проверки можно закрыть.

## Проведённые проверки

| Дата | Вопрос | Итог | Где |
|---|---|---|---|
| 13.09.2026 | Как хранить хозяйство-производитель у вина, не сломав `wineries(*)` у 1.1.0 | Вторая колонка у `wines` и составной ключ `(wine_id, winery_id)` ломают; таблица со своим `id` — нет, в том числе для нескольких хозяйств | `docs/wine_production_winery_tz_2026_09_13.md` §8 |

Правило, найденное 13.09.2026: PostgREST v14.8 считает таблицу связью «многие
ко многим», когда обе её ссылки входят в первичный ключ. Тогда embed между
связанными таблицами становится неоднозначным, если у них есть и прямая связь.
