# ТЗ: поэтапная маршрутизация моделей AI-исследования каталога

## Цель

Снизить стоимость полного исследования вина и винодельни без скрытого
ухудшения качества. Модель выбирается отдельно для каждого этапа, настройки
меняются в admin-web без релиза мобильного приложения и без повторной
выкладки Edge Function.

## Этапы модели

1. `extraction` — чтение заявки и фотографий этикетки, первичная структура.
2. `identity` — разрешение производителя, бренда, bottler и совместных
   проектов по одинаковой поисковой выдаче.
3. `synthesis` — итоговое сопоставление источников и строгий отчёт v3.
4. `editorial` — восстановление публичного описания и вкусового профиля.
5. `knowledge` — предложения Atlas по уже сохранённому отчёту.

Профиль содержит модель каждого этапа и одну резервную модель. Одна модель
может обслуживать несколько этапов. Модель `extraction` обязана принимать
изображения, все модели — поддерживать Structured Output.

## Профили

- `production` — обычная модерация.
- `experiment` — сравнительные запуски. Выбирается явно в workbench и не
  меняет production.

Настройки профиля хранят только ID моделей. Актуальные цены и возможности
берутся сервером из `GET /v1/models` Cloud.ru. Секрет Cloud.ru не попадает в
клиент; admin-web получает только очищенный каталог.

## Снимок конфигурации

При создании job фиксируются профиль, его редакция и ID всех моделей. Перед
первым вызовом модели сервер один раз дополняет снимок тарифами,
возможностями и временем получения каталога Cloud.ru. После этого retry и
пересборка знаний используют тот же снимок, даже если профиль был изменён.

В job и журнале расходов сохраняются модель, этап, токены, тариф и стоимость
каждого успешного ответа. Итоговая стоимость считается по фактически
использованным моделям, а не по одной константе.

## Резервирование

При сетевой ошибке, неподдерживаемой модальности, невалидном строгом JSON или
ошибке провайдера этап один раз повторяется резервной моделью. Повтор и его
стоимость видны в снимке использования. Каталог не изменяется автоматически:
результат по-прежнему проходит модерацию.

## Повторное использование источников

После обычного исследования сохраняется пакет поисковых результатов и
прочитанных страниц. Экспериментальный job может сослаться на пакет job той
же заявки и того же режима. Тогда Yandex Search и браузер не вызываются
повторно, а все модели получают одинаковые доказательства. Фотография и
первичное извлечение обрабатываются заново, чтобы сравнивать vision-модели.

## Admin-web

Экран «Настройки каталога» показывает два профиля, пять этапов, fallback,
возможности и тарифы Cloud.ru. Сохранение запрещается, если extraction не
поддерживает изображения или модель не поддерживает Structured Output.

Workbench позволяет выбрать production/experiment и, для experiment,
повторно использовать последний совместимый пакет источников.

## Приёмка

- Смена профиля не требует нового релиза приложения или деплоя функции.
- Старый job воспроизводим по сохранённому снимку.
- Стоимость совпадает с суммой токенов по тарифам моделей снимка.
- В отчёте видны модели и стоимость по этапам, включая fallback.
- Эксперимент с сохранёнными источниками имеет `search_calls = 0`.
- При недоступности каталога Cloud.ru production продолжает работать на
  `CATALOG_RESEARCH_MODEL` с безопасным встроенным тарифом текущей модели.

Обязательные случаи: Lanson Black Label, Bel Colle Barolo Riserva,
Jean-Marc Brocard Petit Chablis. Дополнительные: Green Life / Van Loveren,
Carlos Serres, Makitra Selection Krasnostop и Xion Albariño.

Кандидаты первого раунда: Xiaomi MiMo-V2.5, Qwen3 VL 30B A3B, GLM-4.6V и
гибрид с DeepSeek V4 Flash для текстовых этапов. Production изначально
остаётся на `openai/gpt-5.4-mini`.
