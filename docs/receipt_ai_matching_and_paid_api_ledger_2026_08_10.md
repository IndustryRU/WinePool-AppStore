# ИИ-сопоставление чеков и учет платных API

## Разбор строк чека

Легкий ИИ-слой работает поверх обычного сопоставления и не использует веб-поиск. В модель передаются только строка чека, распознанные признаки и ограниченный набор (до 30) кандидатов внутреннего каталога. Винодельня считается распознанной только при полном совпадении нормализованного названия или точного alias из базы; нечеткое совпадение по отдельному общему слову не ограничивает поиск.

Режим выбирается в `Админ-панель → Настройки каталога`:

- `off` — ИИ отключен;
- `fallback` — модель вызывается только при недостаточно уверенном или неоднозначном обычном результате;
- `always` — модель участвует в каждой новой уникальной строке чека.

Ответ кэшируется по нормализованной строке, составу кандидатов, модели и версии промпта. Повторное открытие чека не создает новый платный вызов. Изменение каталога или версии промпта естественно создает новый ключ кэша.

Провайдер: Cloud.ru Foundation Models. Модель по умолчанию: `openai/gpt-5-nano`. Яндекс.Поиск для разбора чеков не нужен и не вызывается.

## Единый журнал расходов

`public.paid_api_usage_events` — общий append-only журнал платных интеграций. Он предназначен не только для AI и допускает учет поисковых и других тарифицируемых API.

Основные измерения: дата, провайдер, сервис, сценарий (`operation`), модель, статус, токены, число вызовов модели и поиска, попадание в кэш, стоимость в рублях, задержка, тип/ID объекта и технические метаданные.

Полные промпты, ответы и секреты в журнал не записываются. Для диагностики используются хэш запроса и короткое безопасное описание. Доступ к журналу имеет только администратор каталога.

Текущие сценарии:

- `receipt_matching` — совместимое легкое сопоставление строки чека для прежнего клиента;
- `receipt_matching_v2` — текущий агентский разбор строки с полным учетом входных и выходных токенов;
- `catalog_research` — исследование вина/винодельни, включая стоимость модели и Яндекс.Поиска.

Простой просмотр последних 200 событий и фильтрация по сценарию доступны в `Админ-панель → Расходы AI и API`. Схема уже пригодна для последующего дашборда и графиков без изменения источника данных.
