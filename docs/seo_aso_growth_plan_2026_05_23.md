# WinePool SEO/ASO Growth Plan

Дата: 23.05.2026

## Контекст

WinePool опубликован в RuStore. Следующая задача - начать получать органический трафик без тяжелой рекламы: через страницу приложения в RuStore, лендинг `winepool.ru`, поисковую выдачу Яндекса и контентные страницы под реальные запросы пользователей.

Главное позиционирование продукта остается прежним:

- WinePool - винный дневник 18+.
- Приложение не продает алкоголь, не оформляет заказы и доставку.
- Основная ценность: личный винный погребок, учет вина, история дегустаций, сканирование чеков, карта винных впечатлений, каталог и винный атлас.

## Актуализация 04.06.2026: первые рекламные данные

Первый небольшой трафик дал важный baseline:

- RuStore: 690 просмотров страницы, 10 установок, 0 регистраций;
- YouTube Shorts: 901 просмотр, 47.9% досмотров до конца, 413 уникальных зрителей;
- партнерский пост `Вино и Эль`: около 110 просмотров и 6 реакций.

Вывод для ASO/SEO: карточка и shorts способны доводить людей до установки, но первый запуск должен быть free-entry. До публикации обновления с нейтральным onboarding CTA `В приложение` не запускать дополнительную платную рекламу: трафик будет упираться в старый activation barrier.

После обновления RuStore-страницу нужно синхронизировать с продуктом:

- добавить смысл `Без обязательной регистрации: начните пользоваться сразу`;
- не показывать скриншоты, где первый запуск выглядит как обязательное сканирование чека;
- показать главную как многослойный продукт: чек, погребок, каталог, карта, лента, туризм;
- для tourism pilot подготовить отдельные материалы/скриншоты только после legal/QA решения, не смешивая их с алкогольным commerce.

Для tourism QR запусков не вести first-time туриста сразу в RuStore. QR должен открывать web-карточку с контекстом:

```text
winepool.ru/tourism/o/{operator_slug}
winepool.ru/tourism/o/{operator_slug}/t/{tour_slug}?ref={source}
```

Схема:

- страница оператора показывает лицо бюро, винные туры и вторичный блок `Другие экскурсии оператора`;
- страница конкретного тура является основным QR destination: фото, маршрут, длительность, точка посадки, зачем WinePool нужен туристу;
- CTA на странице: `Открыть в WinePool`, `Установить WinePool`, опционально `Оставить заявку`;
- referral сохраняется в URL и далее в заявке;
- deferred deep link после установки желателен, но MVP допускает повторный tap/rescan после установки.

Важно для поддержки: эти страницы не должны быть отдельными ручными лендингами с собственной копией описания тура. Источник данных один: tourism-модель WinePool (`tourism_experiences`, stops, pickup points, media, vehicles, provider/operator). Web-страница оператора/тура, app-карточка и QR transition page только по-разному отображают один published snapshot.

```text

```

- [wine_cellar_pro_tz_2026_06_23.md](/R:/Flutter/Project/winepool_final/docs/wine_cellar_pro_tz_2026_06_23.md)

## Приоритеты

1. `винный погребок`
   Главный SEO-мост между текущим продуктом и спросом. Использовать в H1/H2, описаниях, карточках преимуществ и отдельной странице.

2. `учет вина` + `коллекция вина`
   Использовать как широкий кластер, но не обещать складской учет или B2B-функции. Формулировка: "личный учет вина" и "личная коллекция вина".

3. `приложение для вина`
   Использовать на главной и отдельной странице для Android/RuStore.

4. `сканер вина` / `сканирование чеков`
   Использовать как функциональный вход. Важно объяснять, что WinePool сканирует фискальный чек/фото чека и помогает перенести вина в личную историю.

5. `винный дневник`, `дневник вина`, `винный блокнот`, `дегустационные заметки`
   Использовать как точный семантический слой: история, оценки, заметки, личные впечатления.

6. `аналог Vivino`
   Сделать отдельную мягкую страницу: "не полная замена Vivino, а русскоязычный винный дневник, погребок и карта".

## План Реализации

### Этап 1 - Сейчас

- Обновить мета-теги главной страницы.
- Добавить на главную блок внутренних SEO-направлений.
- Добавить пять посадочных HTML-страниц.
- Добавить clean URL правила в `.htaccess`.
- Связать страницы между собой и с блоком скачивания.
- После обновления onboarding переписать RuStore first-screen copy и скриншоты: `без обязательной регистрации`, `чек можно добавить позже`.
- Для tourism pilot подготовить web-структуру operator/tour pages и QR/referral URL rules до печати материалов.
- Для tourism web pages использовать один источник данных с приложением, не дублировать туры в статических HTML/landing-файлах.

### Этап 2 - После Индексации

- Подключить Яндекс Вебмастер и отправить страницы на переобход.
- Снять первые данные по показам/кликам через 2-4 недели.
- Доработать title/description по фактическим запросам.
- Добавить FAQPage schema там, где страницы начнут получать показы.
- Сравнить install -> registration до/после onboarding fix, а не оценивать рекламу только по просмотрам.

### Этап 3 - Контентный Рост

- Добавлять 1-2 статьи в месяц под реальные сценарии:
  - как вести домашний винный погребок;
  - как запоминать вина, которые понравились;
  - как не потерять историю дегустаций;
  - как сравнивать вина по регионам и сортам;
  - как пользоваться картой винных впечатлений.

## Метрики

Первый горизонт: 30 дней после индексации.

Отслеживать:

- показы в Яндекс Вебмастере;
- клики по органике;
- переходы на RuStore;
- регистрации в приложении;
- конверсию лендинг -> RuStore;
- запросы, по которым появляются первые показы.
- install -> first home open;
- install -> registration;
- guest first valuable action -> registration;
- YouTube Shorts views, retention, profile clicks and RuStore transitions;
- tourism QR -> tour card -> lead -> registration.

Ожидание: на старте важнее не установки, а появление показов и первых органических переходов. Для нового домена и нового продукта 20-50 установок за первые недели не означает провал; это baseline для проверки конверсии и позиционирования.
