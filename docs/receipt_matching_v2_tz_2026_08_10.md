# WinePool Receipt Matching V2

## Цель

Один и тот же вход должен давать один и тот же глобально упорядоченный список
кандидатов в автоматическом разборе и в ручном подборе. Ошибка внешнего ИИ не
должна оставлять экран пустым и не должна ломать разбор остальных строк чека.

## Совместимость

- Клиент 1.0.6 продолжает использовать существующие функции, таблицы и JSON.
- V2 публикуется отдельным версионированным контрактом; старые RPC и Edge
  Functions не удаляются и не меняют обязательные поля.
- Миграции V2 только добавляющие. Запрещены `DROP`, смена типов и новые `NOT
  NULL` без безопасного значения по умолчанию.
- Перед выкладкой обязательны smoke-запрос старого формата 1.0.6 и запрос V2.

## Единый конвейер

Агентский вариант v2.1 выполняется последовательно:

1. обычный алгоритм извлекает label, сорт, цвет, сахар, тип, регион и возможную винодельню;
2. каталог возвращает расширенный пул до 30 кандидатов, включая поиск по составной товарной идентичности исходной строки;
3. AI получает исходную строку, структурированный блок обычного алгоритма и компактные карточки всех кандидатов;
4. AI ранжирует только переданные идентификаторы;
5. код повторно применяет жёсткие конфликты цвета, сахара и типа независимо от ответа модели.

Винодельня определяется от каталога: полное нормализованное название или
точный alias винодельни должны целиком присутствовать в строке чека. Слова,
уже распознанные как label, сорт, регион или характеристика, запрещено
использовать для fuzzy-определения винодельни. Если точного совпадения нет,
`winery` остаётся пустым, а ручной подбор работает по всему каталогу. Это
предотвращает ложный scope вроде `Стиль Мерло -> Мерло Саук-Дере` и
`Винодел и Сомелье -> Крымский винодел`. Название линейки при этом остаётся
частью товарной идентичности и помогает ранжировать карточки вина.

Сорта обрабатываются аналогично через заранее загруженный каталог канонических
названий и точных aliases. Словарь загружается один раз на сеанс, после чего
все строки чека сопоставляются с ним локально, без отдельного запроса на каждую
позицию и без дополнительного платного вызова ИИ.

1. Бесплатный wine-gate отделяет вероятное вино от остальных товаров.
2. Нормализация строки чека без потери составных названий (`Ф-Стиль`).
3. Извлечение признаков: название/линейка, винодельня, сорта, цвет, сахар,
   тип, регион, объём и год.
4. Retrieval несколькими независимыми запросами. Объединение по `wine.id`.
5. Детерминированная оценка каждого кандидата по одной шкале 0..1.
6. Жёсткие противоречия по явно распознанным цвету, сахару и типу не могут
   получить первый ранг при наличии совместимого кандидата.
7. ИИ получает не более 30 лучших и разнообразных кандидатов, возвращает
   только их ID и не создаёт новые сущности.
8. Финальный порядок сохраняет ограничения шага 6. Автоматический и ручной
   экран используют один результат V2 без локальной пересортировки.

### Бесплатный wine-gate

- Явные невинные маркеры (`пакет`, `ручка`, хозяйственные товары и другие
  поддерживаемые словарём категории) запрещают платный вызов.
- Уверенного совпадения с известной винодельней достаточно: редкая ложная
  сработка дешевле риска пропустить настоящее вино с коротким названием.
- Без винодельни ИИ разрешён при явном винном маркере либо минимум двух
  независимых винных сигналах: сорт, цвет/сахар, тип, бутылочный объём,
  характерное название.
- Пограничная строка остаётся доступна ручному подбору без платного вызова.
- Пропуск записывается как `ai_skipped_non_wine` с нулевой стоимостью.

## Контракт результата

Для каждого кандидата:

- `wine_id`;
- `score` — единый итоговый процент;
- `rank`;
- `matched_signals`;
- `conflicting_signals`;
- `source` (`deterministic`, `ai`, `cache`);
- `requires_review`.

Состояние строки: `matched`, `review`, `no_candidates`, `temporary_failure`.
Отображается до трёх кандидатов с `score >= 0.50`. Все карточки используют
одинаковые действия: `Это оно`; после выбора — `Это не оно`.

## ИИ, повторы и стоимость

- Модель: текущая дешёвая модель Cloud.ru, `reasoning_effort=minimal`.
- Поиск в интернете не используется: модель ранжирует только каталог.
- Ключ кэша включает нормализованную строку, признаки, fingerprint кандидатов,
  модель, prompt и версию pipeline.
- Повторяются только timeout и HTTP 500/502/503/504: максимум две повторные
  попытки с задержками около 350 и 900 мс плюс jitter.
- HTTP 4xx не повторяются.
- При любой окончательной ошибке возвращается детерминированный список.
- Цель: не более одного оплачиваемого запроса на уникальную строку и набор
  кандидатов; ориентир — до 5 рублей на 100 строк, текущая цель около 3 рублей.
- Контрольный пользовательский прогон 10.08.2026 показал около 5–6 копеек для
  сложной уникальной строки и примерно 1 рубль за проведённую серию чеков.
  Это наблюдение для контроля регрессий, а не фиксированный тариф провайдера.

## UX загрузки

После получения чека и до готовности результатов показывается блок
`Подбираем вина из каталога` с тремя shimmer-карточками. Под ним остаётся
пояснение, что разбор обычно занимает несколько секунд. После появления
детерминированного результата shimmer снимается; уточнение ИИ не сбрасывает
выбор пользователя и не возвращает экран в пустое состояние.

## Регрессионный набор

- `РОССИЙСКОЕ ВИНО ... Ф-СТИЛЬ. МЕРЛО` -> сухое Fanagoria выше полусладкого.
- `КЛЕРЕТ СЮР ЛИ` -> соответствующее вино Фанагории доступно.
- `ВАЛЕРИЙ ЗАХАРЬИН ...` -> корректная работа коротких и официальных названий.
- `ВИНО СУХ.КР. 0,75Л` -> стабильный общий ручной поиск без ложной винодельни.
- `ВИНОДЕЛ&СОМЕЛЬЕ Каберне Фран` -> линейка остаётся названием; без точного
  winery/alias в базе поиск не ограничивается винодельней `Крымский винодел`.
- `Пакет п/эт "Фанагория" 30×40` -> допустимый редкий вызов из-за уверенно
  распознанной винодельни.
- Ошибка ИИ 500 -> непустой детерминированный результат.
- Повторное открытие -> cache hit и нулевая дополнительная стоимость.
- Старый запрос 1.0.6 -> прежний совместимый ответ.
