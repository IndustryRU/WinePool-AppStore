# Магазины пользователя и предложения брендов — 1.1.0

## Мои винные магазины

- Точка входа: профиль → «Мои коллекции» → «Мои винные магазины».
- Экран переиспользует канонический источник `get_user_shop_picker_places_v1` и тот же список/карту, что выбор места покупки.
- В режиме коллекции магазин не выбирается: карточка и метка открывают точку во внешних Яндекс Картах, где пользователь может построить маршрут.
- Если пользователь ранее разрешил геолокацию и включён серверный флаг расстояний, список и карточка точки показывают расстояние; маршрут передаёт текущую позицию как начало. Новое разрешение экран сам не запрашивает.
- Потягивание списка вниз повторно проверяет доступность геолокации, получает актуальную позицию и пересчитывает расстояния. На карте для того же действия предусмотрена отдельная кнопка обновления, поскольку жест прокрутки занят перемещением карты.
- Пустое состояние списка также поддерживает pull-to-refresh: пользователь может включить геолокацию в системе и обновить экран без перезапуска приложения.
- Группировка идёт по стране и городу; показываются число магазинов и купленных вин. Дубликаты одной точки схлопываются серверным RPC.
- Старый сценарий выбора места покупки не изменён; совместимость клиента 1.0.6 сохранена.

## Локализация релизного контура

- Новые подписи магазинов, обновления расстояния и перехода на карту локализованы для RU, EN, BE и UZ.
- В профиле локализованы «Экспертный режим», «Поддержать проект», настройка расстояний и связанные диалоги/состояния.
- После обновления ARB-файлов генерация `flutter gen-l10n` проходит без списка непереведённых сообщений.

## Неизвестный бренд после чека

- Мягкий вопрос показывается только после успешного сохранения чека, если есть корректный ИНН, но нет `matched_brand_id`/распознанного бренда.
- Пользователь может пропустить вопрос. Повторная отправка по тому же ИНН обновляет его единственное ожидающее предложение.
- Предложение хранится в `retail_brand_proposals` со статусами `pending`, `approved`, `rejected`.
- В очереди «Бренды магазинов» администратор видит наиболее частое предложение и количество голосов. Оно заранее подставляется в форму нового бренда.
- Привязка ИНН к бренду является одобрением предложений по этому ИНН. Каждому автору один раз начисляется 10 XP через общий журнал `award_user_experience`.
- Полные ключи/промпты не сохраняются; предложение содержит только пользователя, чек, ИНН, юридическое и предложенное публичное название.
