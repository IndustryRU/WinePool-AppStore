### Что вошло (крупные блоки с 1.0.4)

- **WinePool Tourism** — новый раздел: винные туры, дегустации и поездки на
  винодельни; витрина операторов, заявки/лиды с перепиской, трип-центр и
  сохранение билета, QR-переходы. Появился и в онбординге.
- **Универсальное добавление вина** — раньше только по чеку, теперь хаб
  «Добавить вино»: по фото этикетки (сразу камера), по штрихкоду, поиск в
  каталоге, ручной черновик с модерацией. Чек — рекомендуемый путь (цена +
  магазин + точка на карте). Кнопка «Добавить вино» теперь на главной, в
  каталоге, на карте, в профиле и в погребе.
- **Линейки вин** — серии внутри винодельни (напр. «Сокровища Крыма»): чип в
  карточке вина, фильтр каталога, распознавание линейки с этикетки и предзаполнение
  при добавлении, секция «вина этой линейки» на экране сканирования.
- **Распознавание этикетки по полям** — название/винодельня/винтаж/тип/линейка
  раскладываются по своим полям (Yandex OCR), фото бутылки открывается на весь экран.
- **Чеки других стран** — провайдер Беларуси, мультистрановый разбор и
  отображение валюты покупки (RUB/BYN/UZS) в чековом потоке.
- **Погреб** — редактирование бутылки (винтаж/количество/цена/дата), удаление с
  подтверждением, фото на весь экран.
- **Админ-каталог** — слияние дублей виноделен, вин и линеек; алиасы виноделен
  больше не блокируются «надгробиями» слитых записей.

## Накоплено После Опубликованной 1.0.5

Дата анализа: 22.06.2026  
Точка отсчёта: опубликованная `1.0.5+6`, release pointer обновлён коммитом
`055e7dcf Mark 1.0.5 published: in-app release pointer bumped to build 6`.

Текущий код: `pubspec.yaml` уже поднят до `1.0.5+7`. Финальный
`versionName` следующего публичного обновления нужно выбрать перед сборкой
(`1.0.6+7` выглядит естественным вариантом, если оставляем semver-инкремент
после опубликованной `1.0.5`).

### Крупные Блоки

- **Белорусская и узбекская локализация.** Подключены языки `be` и `uz` в
  контроллере языка и профиле, созданы `app_be.arb` и `app_uz.arb` с полным
  набором ключей (`3355` текстовых ключей + `790` metadata-записей), включая
  admin/workbench/suspect/seller. `flutter gen-l10n` создаёт
  `app_localizations_be.dart` и `app_localizations_uz.dart`; `supportedLocales`
  теперь включает `be`, `en`, `ru`, `uz`.
- **Полный l10n-проход по UI.** После 1.0.5 локализованы остатки главной,
  профиля, auth, карты, атласа, каталога, погребка, добавления вина, истории
  чеков, label-scan, tourism-экранов, wine details, winery details, XP-событий,
  admin workbench, reviews и draft details. MVP-лок русского языка снят:
  первый запуск без сохранённого выбора использует системную локаль.
- **Locale-aware release notes.** В `app_release_config` и `app_releases`
  добавлены поля для `en`, `be`, `uz` (`summary_*`, `highlights_*`,
  `release_notes_*`), UI баннера обновления и карточки версии выбирает контент
  по текущему языку с fallback на русский.
- **Мультивалютность и чеки Узбекистана.** Реализованы валюты `RUB/BYN/USD`,
  контекст валюты ручного ввода, единые символы валют, `UZS`, парсер чеков
  Узбекистана и ежедневная синхронизация курсов. Карта покупок и агрегаты
  карты конкретного вина переведены на base-цены, чтобы покупки в BYN/UZS
  корректно участвовали в аналитике.
- **Профиль и настройки.** Меню профиля перестроено: единая секция настроек
  для языка и валюты, одна валюта обновляет display currency и manual-entry
  currency, разделы коллекции/инструментов/открытий стали чище. Bottom sheet
  выбора языка и валюты стал scrollable 70% sheet, чтобы не переполняться при
  5+ языках.
- **Стабильность.** Исправлен краш, который мог возникать у части активных
  пользователей. Этот пункт нужно оставить видимым в release notes, чтобы
  пользователи, столкнувшиеся с падением, понимали причину обновиться.
- **iOS/App Store groundwork.** Исправлен bundle id `ru.winepool.app`, поднят
  iOS deployment target до 16.0, убран конфликт `google_mlkit_barcode_scanning`
  в пользу `mobile_scanner` для QR, отключён iOS binding `ebs_plugin` при
  сохранении Android, обновлён `yandex_mapkit`, добавлена alpha-free iOS icon и
  permission descriptions. Build number поднят до `7`.
- **Лендинг и SEO-страницы.** Обновлён лендинг и посадочные страницы, но
  текущий вариант отдельно помечен как требующий доработки и не выложенный на
  хостинг.

- линейки участвуют в распознавании этикетки через лексикон названий
  (см. следующий пункт);

### Линейка При Сканировании Этикетки

Статус: реализовано; ТЗ `docs/label_line_ocr_tz_2026_06_15.md`.

Раньше распознавание этикетки уже детектило линейку, но результат терялся.
Теперь распознанная линейка проходит весь поток добавления вина по фото:

- предзаполняется в форме нового вина (черновика) рядом с винодельней: показывает
  «из каталога» (существующая линейка) или «новая линейка»; можно сменить/убрать;
- сохраняется в черновике: `draft_wines.line_id` (существующая) или
  `draft_wines.line_name_draft` (новая, подтвердит модератор);
- видна модератору в карточке заявки (раздел данных);
- при одобрении «создать новое вино» предзаполняет пикер линейки в редакторе
  (существующую привязывает автоматически, новую модератор создаёт одной кнопкой
  «Создать и выбрать», идемпотентно — без дублей при повторе);
- линейка усиливает матчинг: вина распознанной линейки получают буст в выдаче
  кандидатов и явную причину «Линейка совпала»;
- линейку можно отредактировать/убрать в карточке черновика пользователя (форма
  редактирования черновика), не только при создании;
- на экране сканирования этикетки, если распознана существующая линейка каталога,
  показывается секция «вина этой линейки в каталоге» (`fetchWinesByLine`) с кнопкой
  «В погреб» у каждого и явным «добавить новое вино линейки» — даже когда конкретного
  вина (напр. сухого сортового Каберне линейки «Сокровища Крыма») в каталоге ещё нет.

Решения этой сессии: новую линейку для не-админа создаём только на одобрении
модератором (в черновике хранится имя); буст матчинга по линейке включён.

### Добавление Вина — UX-проход

Статус: реализовано.

Что сделано на экране «Добавить вино» и вокруг:

  переиспользуем существующий каталог с поиском и фильтрами. Кастомный экран
  поиска удалён; «не нашёл → добавить» из каталога/глобального поиска/баркода
  ведёт сразу в форму создания с предзаполненным названием.
- **Кнопка «Добавить вино» в погребе** перенесена в действие AppBar (рядом с
  share/QR): прежний FAB прятался за общим нижним баром приложения.
- **«+» (добавить вино) в AppBar каталога, карты и профиля** рядом со
  сканированием чека — единый выбор «сразу чек / добавить вручную» на всех
  основных экранах нижнего меню. В профиль также добавлено сканирование чека
