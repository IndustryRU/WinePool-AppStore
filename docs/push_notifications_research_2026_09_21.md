# Push-уведомления: разбор и предложение (21.09.2026)

Повод — отзывы о посещениях (ТЗ H1-02E §4.13): просьба оценить поездку
должна находить гостя сама. Но push нужен шире: статусы заявок, напоминания,
публикации.

## Что есть сейчас

- В приложении push нет совсем: ни пакета в `pubspec.yaml`, ни таблицы
  токенов устройств.
- Уведомления пользователю уже собираются в одну очередь —
  `public.app_notifications` (тип, заголовок, текст, объект, `email_required`).
  Сервис писем на VPS (`/opt/winepool-notifs`, таймер раз в 5 минут)
  рассылает из неё письма. **Push — это второй канал доставки той же
  очереди**, а не новая система уведомлений.
- Заявки: 5 из 12 оставлены из приложения (вошедшие пользователи), 7 — с
  сайта без аккаунта. Push достаётся только первым; для вторых остаются письмо
  и ссылка от партнёра.

## RuStore «Универсальные push-уведомления» — проверено по документации

- **Бесплатно** — так прямо указано на странице инструментов разработчика
  RuStore.
- **Один API на четыре канала:** `POST https://vkpns-universal.rustore.ru/v1/send`,
  провайдеры RuStore, FCM, HMS и **APNS** — то есть iOS тоже закрывается
  через тот же запрос.
- Авторизация RuStore — `project_id` и сервисный токен из консоли RuStore;
  для APNS — ключ Apple (token-based connection), для FCM/HMS — свои ключи.
- Размер сообщения — до 4096 байт.
- На Android транспорт RuStore доставляет через приложение RuStore, а если
  его нет — через другие приложения экосистемы VK (Почта, Дзен,
  Одноклассники).
- Для Flutter есть пакет `flutter_rustore_push` (транспорт RuStore).
- Лимиты частоты в документации не указаны — есть только ошибка «too many
  requests».

Источники: [инструменты разработчика RuStore](https://www.rustore.ru/developer/tools),
[API универсальных push](https://www.rustore.ru/help/en/sdk/general-push-notifications/send-push-notifications/api),
[push-уведомления RuStore](https://www.rustore.ru/help/sdk/push-notifications),
[flutter_rustore_push](https://pub.dev/packages/flutter_rustore_push).

## Предложение

**Канал:** универсальный push RuStore — Android через транспорт RuStore, iOS
через APNS тем же API. Сервер — уже работающий сервис писем на VPS: он
забирает строки `app_notifications` и дополнительно шлёт push на устройства
пользователя.

**Что приходит push'ем (служебное, без рекламы):**

1. заявка подтверждена / отменена, новое сообщение организатора;
2. напоминание накануне поездки: время и место сбора;
3. на следующий день после визита — «Как прошёл вечер? ★★★★★»; нажатие
   открывает оценку в одно касание;
4. то, что уже есть в `app_notifications`: вино или отзыв опубликованы,
   решение модерации;
5. партнёрам в приложении — новая заявка.

Рекламные рассылки — позже и только отдельным переключателем согласия
(ст. 18 38-ФЗ).

**Когда спрашивать разрешение.** Не при первом запуске, а в момент, когда
польза очевидна: после отправки заявки — «Сообщить, когда винодельня
ответит?». Системный запрос iOS показывается один раз, поэтому до него — свой
экран с объяснением.

**Данные:** таблица `user_push_tokens` (пользователь, платформа, провайдер,
токен, дата), в `app_notifications` — статус доставки push; настройки
пользователя — какие типы присылать.

## Что нужно от владельца

1. Проект push в консоли RuStore → `project_id` и сервисный токен.
2. Ключ APNs в Apple Developer (файл .p8, Key ID, Team ID) — приложение уже в
   App Store, аккаунт есть.
3. Сборки приложения для RuStore и App Store — push работает только в новой
   версии.

## Оценка работ

- сервер: таблица токенов, регистрация токена, отправка из сервиса писем,
  настройки типов — небольшой объём;
- приложение: пакеты, нативная настройка iOS (capability Push, APNs) и
  Android, запрос разрешения, переход по нажатию — основной объём;
- проверка — только на реальных устройствах после сборки.
