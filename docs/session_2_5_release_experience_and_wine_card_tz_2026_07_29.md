## 1. Цель и границы

Сделать выпуски (релизы) полноценной публичной частью поиска и карточки вина и
превратить карточку из «паспорта характеристик» во **вход в знание**: каждый
значимый факт о вине связан со статьёй WinePool Atlas.

Трек полностью бесплатный: пользовательский AI/Copilot и внешние search-провайдеры
не вызываются. Session 3 не начинается.

**Не входит:** перевод `offers` на релиз/SKU (это Session 2.6), платёжный контур,
полный Cellar Pro, публикация непроверенных пользовательских фото, перенос Atlas в
БД, автоприменение AI-исследования, коллекции и достижения.

## 4. Миграции (только additive, обратимо)

Файлы: `supabase/migrations/20260729_*.sql`. Порядок применения — как ниже.
Регламент production обязателен: backup + SHA-256 → dry-run (`commit;` → `rollback;`)
→ apply → post-check → **перезагрузка PostgREST** (`NOTIFY pgrst, 'reload schema'` +
`docker restart supabase-rest`). Без последнего шага новые таблицы/RPC не видны
приложению.

RLS во всех новых таблицах — по существующему образцу `wine_vintages`:
публичное чтение опубликованного + полный доступ `is_catalog_admin(auth.uid())`.

### M1. `20260729_add_showcase_flag_to_vintage_images.sql`

```sql
alter table public.wine_vintage_images
  add column if not exists is_showcase boolean not null default false;

create index if not exists wine_vintage_images_showcase_idx
  on public.wine_vintage_images (wine_vintage_id)
  where is_showcase;
```

Backfill **не выполняется**. Существующее поведение сохраняется до того, как
модератор пометит фото витринными.

### M2. `20260729_create_atlas_terms.sql`

```sql
create table if not exists public.atlas_terms (
  id            uuid primary key default gen_random_uuid(),
  slug          text not null unique,
  kind          text not null check (kind in (
                  'appellation','method','approach','certification','eco',
                  'award_program','grape','region','feature','style')),
  title_ru      text not null,
  title_en      text,
  short_ru      text,          -- 1–2 строки: пояснение в чипе и во всплывающем окне
  short_en      text,
  icon_key      text,          -- ключ иконки в приложении
  image_url     text,
  article_slug  text,          -- адрес статьи Atlas; null — статьи ещё нет
  is_published  boolean not null default true,
  created_at    timestamptz not null default now(),
  updated_at    timestamptz not null default now()
);
```

`article_slug` сознательно не является внешним ключом: сегодня статьи живут в
seed-файле, завтра — в БД. Контракт карточки при переносе не меняется.

### M3. `20260729_create_wine_terms.sql`

```sql
create table if not exists public.wine_terms (
  wine_id      uuid not null references public.wines(id) on delete cascade,
  term_id      uuid not null references public.atlas_terms(id) on delete cascade,
  source       text not null default 'moderator'
                 check (source in ('moderator','research','import')),
  confidence   numeric,
  evidence_url text,
  created_at   timestamptz not null default now(),
  primary key (wine_id, term_id)
);

create index if not exists wine_terms_wine_idx on public.wine_terms (wine_id);
```

Термины уровня выпуска в 2.5 не вводятся (данных нет). Расширение — отдельной
таблицей `wine_vintage_terms` с тем же контрактом, когда понадобится.

### M4. `20260729_create_wine_awards.sql`

```sql
create table if not exists public.wine_awards (
  id               uuid primary key default gen_random_uuid(),
  wine_id          uuid not null references public.wines(id) on delete cascade,
  wine_vintage_id  uuid references public.wine_vintages(id) on delete set null,
  program_term_id  uuid references public.atlas_terms(id),
  program_name     text,        -- если термина конкурса ещё нет
  level            text check (level in (
                     'grand_gold','gold','silver','bronze','medal','points','nominee')),
  score            numeric,
  year             int,
  source_url       text,        -- источник факта о награде
  badge_image_url  text,        -- optional: изображение конкретной медали/seal
  badge_source_url text,        -- происхождение изображения
  badge_license_note text,      -- право/лицензия или внутреннее основание публикации
  verified_by      uuid,
  created_at       timestamptz not null default now(),
  updated_at       timestamptz not null default now(),
  constraint wine_awards_program_present
    check (program_term_id is not null or nullif(btrim(program_name),'') is not null),
  constraint wine_awards_badge_provenance
    check (
      badge_image_url is null or (
        nullif(btrim(badge_source_url),'') is not null and
        nullif(btrim(badge_license_note),'') is not null
      )
    )
);

create index if not exists wine_awards_wine_idx    on public.wine_awards (wine_id);
create index if not exists wine_awards_vintage_idx on public.wine_awards (wine_vintage_id);
```

`program_name` — прагматичный запасной путь: модератор может внести награду до
того, как заведён термин конкурса. Тогда чип не кликабелен (правила §10).
Логотип программы хранится в `atlas_terms.image_url`; `badge_image_url` относится
только к конкретной награде. Изображение медали без `badge_source_url` и
`badge_license_note` не публикуется; UI использует единый fallback уровня.

`wines.awards (text[])` **не удаляется** (пустое, legacy). Новые данные пишутся
только в `wine_awards`.

## 6. Политика изображений (Пункт 6) — decision record

**Разделение:** витринное фото (showcase) ≠ доказательное (evidence). Витринность
задаёт модератор флагом `is_showcase`. Непроверенное пользовательское фото
**никогда** не становится публичным hero автоматически.

**Резолвер hero — чистая функция, покрыта тестами:**

1. витринное фото **выбранного** выпуска;
2. витринное фото **любого** выпуска этого вина;
3. `wines.image_url`;
4. премиальный плейсхолдер бренда.

Правила внутри яруса: сначала `is_primary`, затем `sort_order`, затем `created_at`.
Роли `back` и `barcode` в витрину **не допускаются никогда**, даже с `is_showcase`.

Роли, `provenance`, авторство, `is_primary` и `sort_order` сохраняются без потерь.
Evidence-галерея остаётся доступной в модерации отдельно от витрины.
Per-volume/SKU-фото в 2.5 не реализуется; контракт резолвера пишется расширяемым
(параметр объёма может быть добавлен без переписывания) — привязка к объёму в 2.6.

## 7. Выпуски

### 7.1. В карточке вина

- Источник — **только** `wine_vintages` через `WinesRepository`.
  Селектор на `offers.vintage` заменяется.
- Вид: горизонтальная лента — «Все выпуски» + по чипу на выпуск: год или **NV**,
  под ним `release_name`, если заполнен.
- Состояния: **не выбран** → данные уровня вина; **выбран** → hero, ABV, состав,
  награды и отличия этого выпуска. Переключение **обратимо** («Все выпуски»
  возвращает к вино-уровню), навигация и позиция прокрутки стабильны.
- Один выпуск — лента не показывается, но данные выпуска используются.
  Ноль выпусков — блока нет вовсе (сегодня это 99% каталога).
- **Мост к предложениям до 2.6:** если у выбранного выпуска есть год, список
  предложений фильтруется по этому году — прежнее поведение сохраняется. NV и
  выпуски без года предложения не фильтруют.
- Выбор выпуска передаёт `wine_vintage_id` в добавление бутылки
  (`showAddBottleConfirmSheet` уже принимает параметр). Молчаливое добавление
  в погреб запрещено.

### 7.2. В результатах поиска (Пункт 5)

- В карточке кандидата (`catalog_search_candidate_card.dart`) — компактная строка
  доступных выпусков (год/NV + витринная миниатюра по §6). Ранжирование и проценты
  совпадения **не меняются**.
- Три канала: текст, GTIN, этикетка.
- **Exact GTIN, попавший в несколько выпусков одного вина, — не конфликт.**
  Показать варианты и попросить выбрать год/NV; «Не вижу год» и «Нет нужного года»
  сохраняются. Перед реализацией — сверить с уже готовым поведением канала
  штрихкода Session 2 и переиспользовать его.
- Распознанный по этикетке год **поднимает** подходящий выпуск, но не выбирает его
  необратимо: пользователь может сменить.
- «Нет моего выпуска — предложить» переиспользует существующую очередь модерации,
  галерею и multi-contributor механизм Session 2. Новый контур не создаётся.

## 8. Карточка вина — структура

Порядок блоков; блок без данных **не рендерится** (никаких прочерков).

1. **Hero** — фото по §6; поверх: название, винодельня, линейка, рейтинг.
2. **Выпуски** — §7.1.
3. **Ключевые факты** — компактные плитки: цвет, сахар, тип, крепость,
   **температура подачи** (`serving_temperature`, сейчас 57 вин — раньше не
   показывалась), **объём** справочно из `wine_product_codes` (решение №5).
   При выбранном выпуске ABV берётся из выпуска, если он там задан.
4. **Награды** — §9.
5. **Знаки и подходы** — §10 (термины: апелласьон, метод, подходы, сертификации,
   особенности, эко).
6. **Вкус и «Хорошо сочетается»** — существующий профиль вкуса
   (семантика `null` ≠ 0 обязательна: отсутствующее значение не рисуется нулём) +
   аромат и гастрономия. **Приоритет:** `wines.aroma` / `wines.pairing`, если
   заполнены; иначе — существующий подбор по стилю. Технической пометки нет
   (решение №3).
7. **Где купить** — предложения, без изменений до 2.6.
8. **Винодельня** — существующий блок и переход.
9. **Отзывы и оценки** — существующий блок и явный переход к ним.

Обязательно проверить: Android/iOS/web, длинные названия, отсутствие фото, один
выпуск, много выпусков, NV, неполные данные, узкие экраны.
Модераторские действия через «⋮» и маршруты редактирования сохраняются.

## 9. Награды — поведение (решение №1)

- **Выпуск не выбран:** блок «Награды» показывает награды **всех** выпусков вина,
  горизонтальной лентой, сгруппированные по годам (свежие первыми). В заголовке —
  счётчик, напр. «Награды · 7». Элемент: значок уровня (золото/серебро/бронза/…),
  название конкурса, год.
- **Выпуск выбран:** заголовок «Награды выпуска 2021», показаны награды этого
  выпуска; обязательна ссылка **«Все награды вина · N»**, возвращающая к полному
  списку.
- **У выбранного выпуска наград нет:** пустоту показывать запрещено — она читается
  как оценка качества. Текст строго нейтральный, про данные, а не про вино:
  «У выпуска 2023 наград не отмечено», рядом — «Смотреть награды других
  выпусков · N». Если у вина наград нет вообще — блока нет.
- Награда без `wine_vintage_id` (год неизвестен) показывается на вино-уровне и не
  исчезает при выборе выпуска — помечается как относящаяся к вину.
- Тап по награде → статья Atlas о конкурсе (через `program_term_id.article_slug`).
  Термина/статьи нет → правило §10.

## 10. Термины и связь с Atlas

- Рендер единообразный: **чип** — иконка + название; рядом или под ним короткое
  пояснение из `short_ru`.
- **Тап при наличии `article_slug`** → статья Atlas (`/wine-atlas/:slug`).
- **Тап при отсутствии статьи** (решение №2) → всплывающее окно с `short_ru`;
  переход не предлагается. Факт **не скрывается**.
- Если и `short_ru` пуст — чип показывается статично, без действия.
- Эко-флаги (`is_pet_nat`, `is_organic`, `is_biodynamic`, `is_natural`) **остаются
  булевыми полями** (фильтры каталога не трогаем), но на карточке рисуются тем же
  чипом: для каждого заводится термин `kind='eco'` со стабильным slug
  (`pet-nat`, `organic`, `biodynamic`, `natural`). Существующие бейджи заменяются
  на единый рендер.
- Показ по умолчанию — не более 4 чипов + «ещё N»; полный список в экспертном
  режиме или по тапу «ещё».
- Наполнение справочника в 2.5 — минимальный seed модератором (эко + те термины,
  что реально встречаются). Массового импорта из отчётов исследования в этой
  сессии **нет**.

## 13. Админские поверхности ввода (обязательно)

**Без этого раздела Session 2.5 рождается мёртвой.** На 29.07.2026 наград 0,
терминов 0 (таблицы ещё нет), выпусков 15 на 1041 вино, объёмов 2. Если реализовать
только карточку, пять из шести новых блоков не отрисуются ни на одном вине —
ни показать, ни проверить их будет нельзя.

Поэтому в объём 2.5 входят экраны ввода в **admin web** (уже задеплоен).
Переиспользовать существующие админские паттерны, параллельную админку не строить.

1. **Справочник терминов** (`atlas_terms`): список с фильтром по `kind` + форма
   (slug, вид, `title_ru/en`, `short_ru/en`, `icon_key`, `image_url`,
   `article_slug`, `is_published`). Минимальный seed при запуске — четыре эко-термина
   со стабильными slug: `pet-nat`, `organic`, `biodynamic`, `natural`.
2. **Термины вина** (`wine_terms`) — в существующем экране редактирования вина:
   добавление термина поиском по справочнику и удаление. `source = 'moderator'`.
3. **Награды вина** (`wine_awards`) — там же: добавить/изменить/удалить награду
   (конкурс из справочника **или** текстом в `program_name`, уровень, год,
   выпуск — необязателен, `source_url`; optional `badge_image_url` только вместе с
   `badge_source_url` и `badge_license_note`).
4. **Витринность фото** (`is_showcase`) — в существующем `AdminWineReleaseManager`:
   переключатель у релизного фото. Для ролей `back` и `barcode` переключатель
   недоступен с пояснением (см. §6).

## 14. Эталонное вино (предусловие приёмки)

До реализации карточки владелец/модератор заполняет **1–2 эталонных вина** через
§13. Они нужны и дизайну, и разработке, и QA — иначе всё проверяется вслепую.

Состав эталона: 2–3 выпуска (включая один NV) с витринными фото; 3–5 наград
разного уровня и года, из них **одна без выпуска** (проверка вино-уровня); 4–6
терминов разных видов (апелласьон, метод, сертификация, эко); объёмы в
`wine_product_codes`; заполненная `serving_temperature`.

Идентификаторы эталонных вин фиксируются в handoff и становятся опорой
QA-матрицы Session 2.5.

## 15. Экспертный режим

Переиспользуется существующий `expertModeProvider` (ключ `expert_mode`).
При включении на карточке: лента выпусков раскрыта по умолчанию, показаны все
термины без свёртки, видны объёмы/SKU и источники данных (`evidence_url`,
`source_url`). Новый тумблер не вводится.

## 16. Тесты

Обязательный минимум (unit/widget):

- резолвер hero: все четыре яруса, приоритет `is_primary`/`sort_order`,
  исключение ролей `back`/`barcode`, игнорирование не-showcase фото;
- выбор выпуска: передача корректного `wine_vintage_id` дальше, обратимость,
  поведение при 0/1/N выпусках и NV;
- награды: группировка по выпускам, фильтрация при выбранном выпуске, награда без
  выпуска, нейтральный текст при отсутствии наград у выпуска;
- термины: чип со статьёй → переход, без статьи → пояснение, без пояснения →
  статичный чип; свёртка «ещё N»;
- вкусовой профиль: `null` ≠ 0;
- приоритет `pairing`/`aroma` над подобранными сочетаниями.

Регрессия: профильные тесты Session 2 остаются зелёными, включая guardrail
`free_paths_no_copilot_guard_test.dart` (бесплатные пути не ссылаются на
Copilot/внешний search).

Анализ: targeted `flutter analyze` по изменённым файлам; полный analyze
оценивается относительно текущего baseline, посторонние старые замечания не чинятся.

## 17. Порядок работ

Работа делится на два потока: фундамент от визуала не зависит и начинается сразу,
дизайн согласуется параллельно.

**0. Аудит** существующего поведения релизов в канале штрихкода (не дублировать) +
краткий evidence-отчёт.

**Поток А — фундамент (можно начинать немедленно):**

1. M1 + резолвер изображений с тестами (фундамент для §7–§9).
2. M2–M4, модели, repository, провайдеры.
3. Админские поверхности ввода (§13) + seed эко-терминов.

**Поток Б — завершён 30.07.2026:** визуальная концепция карточки и редакция 3
утверждены владельцем. Зафиксированный визуальный контракт:
`docs/session_2_5_wine_card_revision_3_design_brief_2026_07_30.md`. Реализация
карточки разблокирована, но должна следовать этому контракту и основному ТЗ.

**Дальше последовательно:**

4. Эталонное вино (§14) — владелец заполняет через готовые экраны §13.
5. Карточка вина (§8) — включая §7.1, §9, §10 — по утверждённому макету,
   проверяется на эталонном вине.
6. Выпуски в результатах поиска (§7.2).
7. Переименование Atlas (§11), строки в ARB.
8. Тесты, QA-матрица Session 2.5, handoff.

Admin web можно собирать и деплоить без дополнительного согласования.
**APK/AAB/IPA не собирать:** Android-сборку делает владелец; store-артефакты
готовятся только после Session 2.6 для версии `1.1.0`.
